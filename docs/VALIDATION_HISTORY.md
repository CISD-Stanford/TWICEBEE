# Validation history and verification scope

The unchanged research implementations have existing scientific validation evidence. Primary TWICEBEE's retained validation covered seven conduct and three terminal tests, including terminal processing that preserves trial conduct and its RNG stream. MOB has existing isolated and integrated deterministic validation of complete decision-time batches, shape closure, persistent accounting and retained conduct/safety/terminal rules. Those historical scientific suites and full study simulations are outside the included bounded release checks.

The included research check script loads both engines and evaluates ten established comparisons using one fixed simulated TWICEBEE illustration and one deterministic MOB working update. It retains the original expected results and floating-point conventions. The MOB decimal comparison uses its existing absolute-scale tolerance of 1e-12, alongside exact arithmetic-equivalent shape and ledger comparisons; this is not a new acceptance threshold.

The CSV interface has existing verification using seven deterministic operational groups, included as `tests/run_targeted_tests.R` and `tests/event_helpers.R`. They cover administered-event agreement with direct core calls; duplicate/pending-outcome rejection; preview/confirmation behavior; common-time order and accepted-history protection; hold/discontinuation; replay, idempotence and atomic output handling; and finalization/status/contiguous-sequence behavior. The complete manual example uses explicitly fictional outcomes and fresh R processes.

Previously documented local verification used R 4.4.1 on macOS 26.6, Apple arm64 (`aarch64-apple-darwin20`). This is one verified environment, not a compatibility range. CSV operation requires local POSIX symbolic links and atomic rename. Windows, Linux, network/cloud-synchronized trial directories, accepted-history amendments, parameter customization and unavailable/lost evaluable outcomes are not established by these records. No clinical or regulatory validation is claimed.

Re-running the included checks verifies the stated bounded expectations in the environment actually used. It does not reproduce the full manuscript, establish comparative operating characteristics, validate a clinical protocol, or authorize treatment. All supplied demonstration inputs are simulated or explicitly fictional; no real patient dataset is supplied.
